# @cos/web

The COS web app: club dashboards, activity feed, document hub.
Next.js (App Router); talks only to `services/api` over HTTP and WebSockets.

## Running it

```bash
pnpm install
pnpm --filter @cos/web dev   # http://localhost:3100
```

## Current state (phase 1)

One surface: the club event calendar.

- Month grid with per-day event chips, an event detail panel, and an officer-only composer.
- Officer and member render the same component tree. Every difference is a capability check (`useCan('event:create')`), never a role comparison, so real auth can slot in without touching the views.
- Events are held in an in-memory `EventRepository` (`lib/in-memory-event-repository.ts`) seeded on load. There is no persistence yet: a refresh restores the seed. Swapping in an HTTP-backed repository is a one-line change in `lib/event-store.tsx`.
- A dev-only Officer/Member switch in the top nav stands in for auth, which is still an open question.

## Design system

UI is built on [Astryx](https://github.com/facebook/astryx) (`@astryxdesign/core`).
Read `AGENTS.md` in this directory before adding UI: it is generated by `npx @astryxdesign/cli init` and carries the conventions (no raw `<div>` for layout, tokens instead of hardcoded values, discover components with `astryx build` / `astryx component` before writing new ones).

The COS theme source is `theme/cos-theme.ts`, compiled to `theme/cos.css` + `theme/cos.js`.
Those artifacts are generated; after editing the source theme, rebuild them:

```bash
npx @astryxdesign/cli theme build theme/cos-theme.ts
```

## Known gaps

- No routing beyond `/`. More surfaces arrive with v0.2, at which point a `SideNav` replaces the top-nav-only shell.
- Light mode only. The theme defines dark tokens but dark has not been designed.
- `components/calendar/event-chip.module.css` is a documented workaround for a truncation gap in Astryx's interactive `Token`; it should be deletable if that is fixed upstream.
